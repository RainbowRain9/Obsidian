# 5.3 TCP协议

传输层在TCP/IP模型中起到重要作用，为应用层提供服务来实现通信。传输层有两个主要协议：用户数据报协议（UDP）和传输控制协议（TCP）。TCP，由RFC 793文件定义，是一个**面向连接的、可靠的、基于字节流**的传输层通信协议。它负责处理应用层发送的8位字节数据流，将其分成适当长度的报文段，并交给IP层传输。

## 5.3.1 TCP概述

TCP (Transmission Control Protocol) 是传输层提供的主要协议之一。它与UDP不同，提供了更高级的服务。

TCP的主要特点包括：

- **面向连接**：在使用TCP通信的两个实体之间，在发送数据之前需要**先建立连接**，以确保接收方在线并准备接收数据。
- **可靠**：TCP提供**可靠传输服务**。它能**保证接收方一定能收到数据**，并且收到的数据**不会出现差错**。它通过一系列机制（如校验和、确认、超时重传）来确保数据的完整性和可靠交付。
- **基于字节流**：应用层向TCP发送的是**8位字节表示的数据流**。TCP将这个数据流**分区成适当长度的报文段**进行传输。
- **报文段处理**：TCP将数据流分成报文段，其长度通常受限于计算机连接网络的数据链路层的**最大传输单元 (MTU)**。
- **交给IP层传输**：TCP将分好的报文段交给IP层，由IP层通过网络传送给接收端的TCP层。

## 5.3.2 TCP服务模型

TCP服务模型描述了TCP如何为应用层提供通信功能。

- **套接字 (Socket)**：TCP使用主机的**IP地址加上主机上的端口号作为TCP连接的端点**。这种端点就叫作**套接字**或插口。
- **表示方法**：套接字用**(IP地址：端口号)**表示。
- **抽象表示**：它是网络通信过程中**端点的抽象表示**。
- **包含信息**：一个套接字包含进行网络通信必需的五种信息：
    1. 连接使用的协议
    2. 本地主机的IP地址
    3. 本地进程的协议端口
    4. 远端主机的IP地址
    5. 远端进程的协议端口

TCP与UDP一样，**利用端口号来实现对应用程序的复用和分用功能**。端口号是传输层解决程序复用和分用功能的关键，用于对应用程序进行编址。

## 5.3.3 TCP报头的格式

TCP报文段包含一个可变长度的首部和数据部分。TCP报头包含多个字段，各字段有其特定的位数和含义。

TCP报头的主要字段及其描述如下：

- **源端口 (Source Port)**：**16 位**。标识发送方应用程序的端口号。
- **目的端口 (Destination Port)**：**16 位**。标识接收方应用程序的端口号。
- **序列号 (Sequence Number)**：**32 位**。用于**标识报文段在原始数据的位置**，并用于数据重组。其取值范围是0~232-1。每个序列号值用于对应用层数据里**某个字节进行编号**。
- **确认号 (Acknowledgment Number)**：**32 位**。接收方用于表示收到的数据。其值表示**下一个期待接收的报文段的序号**。
- **报头长度 (Header Length)**：**4 位**。表示**TCP报文段报头的长度**。由于报头长度是可变的（因为有选项字段），这个字段指明了报头实际占用了多少个32位字。
- **保留位 (Reserved)**：**6 位**。此字段留作将来使用，目前在使用过程中都**置为0**。
- **控制位 (Control Flags)**：**6 位**。包含位码或标志，通过不同取值表示当前TCP报文段的用途和功能。这6个位分别为：**URG, ACK, PSH, RST, SYN, FIN**。
- **窗口大小 (Window Size)**：**16 位**。接收方用该字段来表示接收方在下一次传输中**可以接收的字节的数量**。窗口大小范围是0~216-1。该字段用于**指定发送方的发送窗口大小**。
- **校验和 (Checksum)**：**16 位**。用于对报文段报头和数据进行**错误检查**。
- **紧急 (Urgent Pointer)**：**16 位**。表示数据是否紧急。**只有控制位里的URG标志位被设置为1时该字段才有意义**。
- **选项 (Options)**：长度可变，**最长可达40字节**。选项主要分为：最大报文段长度（MSS）、窗口扩大选项、时间戳选项、选择确认（SACK）选项等。

## 5.3.4 TCP连接建立

TCP连接的建立通常使用**三次握手**的过程。

1. **第一步**：发送方应用进程发送**SYN消息**给接收方，请求发送数据给接收方。SYN标志位被设置。
2. **第二步**：接收方回复**SYN+ACK消息**给发送方。SYN标志位和ACK标志位都被设置。此消息允许发送方传输数据过来，同时请求发送方传输数据给接收方（通过SYN），并确认收到了发送方的SYN（通过ACK）。
3. **第三步**：发送方回复**ACK消息**给接收方。ACK标志位被设置。此消息同意对方传输数据过来，并确认收到了接收方的SYN+ACK。

完成这三步后，双方都确认对方已准备好进行数据传输，TCP连接正式建立。

## 5.3.5 TCP连接释放

TCP连接的释放通常是一个**四次挥手**的过程。

1. 当发送方不再需要发送数据给接收方时，它将发送**FIN消息**给接收方。FIN标志位被设置。
2. 接收方收到FIN消息后，将回复**ACK消息**，确认收到发送方的终止连接请求。此时，发送方不能再发送数据给接收方。接收方可能还有数据需要发送给发送方。
3. 当接收方也不再需要发送数据给发送方时，它也发送**FIN消息**给发送方。FIN标志位被设置。
4. 发送方收到FIN消息后，回复**ACK消息**，确认收到接收方的终止连接请求。此时，接收方也不能再发送数据给发送方。至此，**双方连接都释放掉了**。

## 5.3.6 流量控制

TCP提供**流量控制功能**，目的是解决**接收方处理数据的速度可能跟不上发送方发送数据的速度**的问题。

- **协商窗口大小**：双方在**连接建立阶段会协商好初始的发送窗口大小**。发送方会按照该发送窗口来传输数据，以保证接收方能够顺利处理接收到的数据。
- **实时调整**：在数据开始发送后，接收方还可以**实时地根据处理情况，向发送方发出反馈信息**，以调整发送方的发送窗口大小。
- **实现机制**：流量控制功能通过TCP报头的**16位的窗口大小字段**来实现。
- **窗口单位**：窗口大小字段的单位是**字节**。
- **限制**：发送方的发送窗口**不能超过接收方给出的接收窗口的数值**。
- **滑动窗口**：接收方在处理接收的字节的同时，不断调整发送方的发送窗口大小的过程被称为**滑动窗口**。

## 5.3.7 差错控制

TCP提供**可靠传输服务**，通过差错控制机制来保证数据传输的可靠性。主要机制包括：

1. **校验和 (Checksum)**：TCP报头中包含一个**16位的校验和字段**，用于**检查报文段是否受到损伤**。
2. **确认 (Acknowledgment)**：
    - 发送方的TCP对于发送出去的报文段，利用TCP报头的**序列号字段**进行编码。
    - 对于收到的报文段，TCP需要向发送方**回复确认控制信息**。
    - 确认控制信息一方面表明**已经正确收到之前的数据**。
    - 另一方面，通过设置**确认号字段值**来说明其**希望发送方发送的下一个报文段的序列号**。
3. **超时重传 (Timeout Retransmission, RTO)**：
    - 发送方的TCP为**每个发送出去的报文段分别设置了一个重传超时（RTO）计时器**。
    - 当计时器时间到期（**超时**），TCP**重新发送丢失或出错的报文段**，并**重启计时器**。

**TCP的重新排序**：

- TCP报文段到达目标设备时其顺序**可能是混乱的**。原因包括差错或丢失重传，或多个报文段选择不同路径。
- 为了让目的设备理解原始消息，需要**重组这些报文段**以恢复原有顺序。
- 重组的办法是利用TCP报头的**序列号字段**，该字段标明了每个报文段在原始数据的先后顺序，通过该字段即可对顺序混乱的报文段进行重组。

## 5.3.8 拥塞控制

**拥塞**发生在网络运行期间，若网络节点对网络整体的某一资源的需求**超过了网络所能提供的可用部分**，网络性能就会下降。

造成网络拥塞的原因包括：

- 网络某节点（如路由器）的多条流入线路有分组到达，并需要**同一输出线路**。
- 路由器**资源有限**。

为了进行拥塞控制，TCP使用四种主要算法：

1. **慢开始 (Slow-start)**
2. **拥塞避免 (Congestion Avoidance)**
3. **快重传 (Fast Retransmit)**
4. **快恢复 (Fast Recovery)**

**慢开始算法具体工作流程**：

- 当TCP连接建立时，拥塞窗口 (cwnd) **初始值为1个最大报文段(MSS)大小**。
- 发送端按照拥塞窗口大小发送数据。
- **每当有一个报文段被确认，cwnd就增加至多1个MSS大小**。
- cwnd按**指数规律增长**。
- 为了控制增长，设置一个**慢开始门限 (ssthresh)**。
- ssthresh的用法：
    - 当`cwnd < ssthresh`时，使用慢开始算法调整cwnd。
    - 当`cwnd > ssthresh`时，改用拥塞避免算法调整cwnd。
    - 当`cwnd = ssthresh`时，慢开始与拥塞避免算法任意选择。

**拥塞避免算法具体工作流程**：

- 每经过一个往返时间 (RTT)，发送方的拥塞窗口cwnd**加1**。这称为**加法增大**。
- 无论发送方处于慢开始还是拥塞避免阶段，**只要发送方没有收到某个分组的确认消息**，即可判断网络出现拥塞。
- 此时，将**慢开始门限设置为出现拥塞时的发送窗口大小的一半**。这称为**乘法减少**。
- 然后把**拥塞窗口重置为1**，继续执行慢开始算法。

**快重传算法**：

- 快重传算法**不需要等待重传计时器超时**。
- 只需收到**三个重复的确认ACK**即可断定分组丢失，从而**重传分组**。
- 为此，快重传算法需要接收方在收到一个顺序混乱的报文段后**马上发出重复确认消息**。

**全局同步 (Global Synchronization)**：

- 当路由器收到过多分组以至于缓存不够用时，会丢弃后续分组。如果简单按先来先丢策略，可能影响很多TCP连接。
- 这会导致这些连接的源系统**同时认为网络进入拥塞状态**，而同时进入慢开始状态。
- 结果是网络流量**突然下降很多**，而网络恢复一段时间后流量又会突然增大很多。这被称为全局同步。

**随机早期检测算法 (Random Early Detection, RED)**：

- 为解决全局同步现象，路由器采用RED算法。
- 路由器为分组队列设置**两个门限：最小门限min和最大门限max**。
- 当分组到达时，RED计算**平均队列长度**。
- 根据平均队列长度处理到来的分组：
    - 平均队列长度小于最小门限——**把新到达的分组放入队列排队**。
    - 平均队列长度在最小门限与最大门限之间——则按照**某一概率将分组丢弃**。
    - 平均队列长度大于最大门限——**丢弃新到达的分组**。

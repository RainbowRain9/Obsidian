# 5.2 UDP协议

传输层提供了两个主要协议：用户数据报协议（UDP）和传输控制协议（TCP）。UDP，由RFC 768文件定义，是传输层的一个重要协议。
123
## 5.2.1 UDP概述

UDP（User Datagram Protocol）是一种简单的、无连接的传输层协议。与TCP相比，UDP的主要特点包括：

- **无连接**: UDP通信的两个实体之间在发送数据前不需要事先建立连接。这意味着发送方直接发送数据报，不确认接收方是否在线或准备接收。
- **不可靠**: UDP提供的是不可靠传输服务。它无法保证接收方一定能收到数据，即使数据收到，也不能保证数据没有错误。这意味着UDP不进行丢失或出错报文段的重传。
- **面向报文**: UDP传输的是用户数据报，保持了应用层交付的报文边界。
- **缺乏拥塞控制**: UDP本身不提供拥塞控制机制。如果网络发生拥塞，UDP发送方不会主动降低发送速率。
- **首部开销小**: UDP的首部非常简单，开销较小。

## 5.2.2 UDP报头的格式

UDP用户数据报包含一个固定长度的首部和可变长度的数据部分。标准的UDP首部是 **8个字节** 长。虽然来源未提供详细的图示，但根据实践分析（见下文课堂练习），其主要字段包括：

- **源端口 (Source Port)**: 标识发送方应用程序的逻辑端口号。占 **2个字节** (16位)。
- **目的端口 (Destination Port)**: 标识接收方应用程序的逻辑端口号。占 **2个字节** (16位)。
- **长度 (Length)**: UDP用户数据报的总长度，包括首部和数据部分。占 **2个字节** (16位)。此字段的最小值为8（仅包含头部）。
- **校验和 (Checksum)**: 用于对UDP报文段（包括伪首部、UDP首部和数据）进行错误检查。占 **2个字节** (16位)。在某些情况下，UDP校验和是可选的（尽管通常建议计算）。

一个UDP用户数据报的总长度由其头部中的“长度”字段指明，数据部分的长度可以通过总长度减去固定的8字节头部长度得到。

## 5.2.3 UDP的操作与使用

传输层协议如UDP和TCP通过使用端口号来实现应用程序的**复用**和**分用**功能。端口号是对应用程序进行编址的一种方式。端口号的范围从0到65,535，指的是逻辑端口号。

在网络通信中，本地主机上发起通信的应用程序使用的端口号称为**源端口号**，而与本地主机通信的远程主机上的目的应用程序使用的端口号称为**目的端口号**。

端口号根据其范围被划分为几类：

|分类|范围|描述|
|:--|:--|:--|
|公认端口 (Well-known)|0 - 1,023|通常用于识别服务器上运行的一些常用服务。|
|注册端口 (Registered)|1,024 - 49,151|由IANA分配给申请者以用于特定进程或应用程序。|
|动态或私有端口 (Dynamic/Private)|49,152 - 65,535|通常用于客户端发起连接时系统临时分配的端口。|

常用服务对应的公认端口示例如下：

|程序或服务|公认端口号|
|:--|:--|
|FTP|21|
|SMTP|25|
|HTTP|80|
|TELNET|23|
|HTTPS|443|
|SNMP|161|
|TFTP|69|

UDP不像TCP那样对数据进行重新排序。报文段到达目的地时其顺序可能混乱，但UDP不会对其进行处理。

### 5.2.3.1 课堂练习解析

根据提供的UDP用户数据报首部十六进制表示：`06 32 00 45 00 1C E2 17`，我们可以解析其各个字段的值并回答问题。

**UDP头部十六进制:** `06 32 00 45 00 1C E2 17`

1. **源端口 (Source Port)**: 十六进制表示为 `06 32`。 将其转换为十进制：
    
    ```
    // 十六进制转十进制计算
    string hex_source_port = "0632";
    int source_port = 0;
    for (char c : hex_source_port) {
        source_port *= 16;
        if (c >= '0' && c <= '9') {
            source_port += c - '0';
        } else if (c >= 'A' && c <= 'F') {
            source_port += c - 'A' + 10;
        } else if (c >= 'a' && c <= 'f') {
            source_port += c - 'a' + 10;
        }
    }
    // 0632(hex) = 0*16^3 + 6*16^2 + 3*16^1 + 2*16^0
    //           = 0 + 6*256 + 3*16 + 2
    //           = 1536 + 48 + 2 = 1586
    ```
    
    源端口号是 **1586**。
    
2. **目的端口 (Destination Port)**: 十六进制表示为 `00 45`。 将其转换为十进制：
    
    ```
    // 十六进制转十进制计算
    string hex_dest_port = "0045";
    int dest_port = 0;
    for (char c : hex_dest_port) {
        dest_port *= 16;
        if (c >= '0' && c <= '9') {
            dest_port += c - '0';
        } else if (c >= 'A' && c <= 'F') {
            dest_port += c - 'A' + 10;
        } else if (c >= 'a' && c <= 'f') {
            dest_port += c - 'a' + 10;
        }
    }
    // 0045(hex) = 0*16^3 + 0*16^2 + 4*16^1 + 5*16^0
    //           = 0 + 0 + 64 + 5 = 69
    ```
    
    目的端口号是 **69**。
    
3. **用户数据报的总长度 (Total Length)**: 十六进制表示为 `00 1C`。 将其转换为十进制：
    
    ```
    // 十六进制转十进制计算
    string hex_total_length = "001C";
    int total_length = 0;
    for (char c : hex_total_length) {
        total_length *= 16;
        if (c >= '0' && c <= '9') {
            total_length += c - '0';
        } else if (c >= 'A' && c <= 'F') {
            total_length += c - 'A' + 10; // 'C' is 12
        } else if (c >= 'a' && c <= 'f') {
            total_length += c - 'a' + 10;
        }
    }
    // 001C(hex) = 0*16^3 + 0*16^2 + 1*16^1 + 12*16^0
    //           = 0 + 0 + 16 + 12 = 28
    ```
    
    用户数据报的总长度是 **28 字节**。
    
4. **数据部分长度 (Data Length)**: UDP头部固定长度为8字节。 数据部分长度 = 总长度 - 头部长度 数据部分长度 = 28 字节 - 8 字节 = **20 字节**。
    
5. **用户数据报是从客户端发送给服务器还是服务器发送给客户？** 目的端口号是 69，属于公认端口号范围 (0-1023)，通常用于识别服务器上的常用服务。源端口号是 1586，属于注册端口号范围 (1024-49151)。在网络通信中，发起通信的应用程序（客户端）通常使用注册端口或动态/私有端口范围内的临时端口作为其源端口，而与之通信的远程主机上的目的应用程序（服务器）则使用一个公认端口作为其目的端口。 因此，这个用户数据报很可能是从**客户端发送给服务器**的。
    
6. **使用UDP的这个服务程序是什么？** 目的端口号是 69。根据常用服务对应的公认端口列表，端口号 69 对应的服务程序是 **TFTP (Trivial File Transfer Protocol)**。
